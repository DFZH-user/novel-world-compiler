# 阶段 0：小说工程数据底座

## 目标

阶段 0 不猜人物、不生成关系、不编造地图。它只负责把用户提供的 TXT 小说变成一个可重复打开、可人工修订、可追溯到原文字节位置的本地工程。

后续四个分析模块——人物卡、人物关系、时间线、世界地图——必须读取本阶段的活动源修订、段落、分块和证据锚点，不得各自重新切割小说。

## 工程布局

```text
工程名.novelworld/
├─ project.json
├─ novel.db
├─ sources/
│  └─ rev_<hash>/
│     ├─ original.txt
│     └─ normalized.txt
└─ tmp/
```

- `original.txt`：逐字节复制的原始文件。
- `normalized.txt`：按确认编码解码为 UTF-8，只统一 BOM 和换行。
- 两者创建后均不被结构编辑修改；重新导入会产生或复用源修订。
- `novel.db`：标准 SQLite 文件，由独立数据进程通过 Node 内置 `node:sqlite` 直连；启用 WAL、`synchronous=FULL`、外键、在线备份和完整性校验。

## 稳定标识与证据

- 源修订 ID：`SHA-256(原始字节哈希 + 确认编码)`。
- 段落 ID：`SHA-256(源修订 + UTF-8 起止字节 + 正文哈希)`。
- 自动章节初始 ID 为 UUID；拆分和合并写入 `chapter_lineage`。
- 分块 ID：`SHA-256(源修订 + 分块方案版本 + 核心段落范围)`。
- 兼容证据锚点保留规范文本 UTF-8 字节区间；规范 `source_spans` 另存段落内 UTF-16 code unit 起止位置、逐字引文 SHA-256、前后文和 `exact/normalized/ambiguous/invalid` 对齐状态。

SourceSpan ID 是确定性的。重复引文没有足够位置约束时会标为 `ambiguous`，绝不静默指向第一次出现。

## 分块默认值

| 参数 | 默认值 |
|---|---:|
| 核心目标 | 8,000 字符 |
| 软上限 | 10,000 字符 |
| 硬上限 | 12,000 字符 |
| 前文重叠 | 500 字符 |
| 后文重叠 | 500 字符 |

核心段落在同一方案中只出现一次；重叠段落只作为上下文出现。人工排除的段落不会进入新分块方案。V2 按章节、场景分隔符、空行、普通段落依次评分，记录输入指纹、边界原因与内容哈希；完全相同的连续重建会复用现有方案。单个不可拆自然段超过硬上限时显式标为 `oversized_paragraph`，不会在句中静默硬切。

段落全文索引使用 FTS5 trigram。三字及以上中文查询走索引，较短查询走精确扫描；索引由数据库触发器随段落增删改保持同步。

## 任务恢复

长任务保存状态、输入、进度、检查点和租约。应用重开工程时，遗留的 `running` 任务不会被误报为完成，而会变为 `queued` 并显示“等待恢复”。恢复操作会从原输入创建新的尝试；失败尝试保留为审计记录。

## 备份边界

`.novelproj` 是 ZIP 容器，包含：

- `manifest.json`
- SQLite 快照 `novel.db`
- `sources/` 下所有原始与规范文本
- `checksums.sha256.json`

它不包含 API 密钥、应用日志、临时文件或系统安全存储内容。

## 已验证范围

- 编码：UTF-8、GB18030、UTF-16 BOM，以及候选排序。
- 标题：中文章/回/卷/部/篇、序章/尾声/番外、英文 Chapter/Book/Part。
- 完整链路：创建、导入、章节编辑、段落排除、检索、证据锚点、分块、备份、关闭重开。
- 失败与恢复：I/O 失败不激活修订；陈旧运行任务重开后进入恢复队列。
- 文件规模：约 1 MB、10 MB、50 MB 中文 TXT。
- 桌面安全：渲染进程无 Node/require，生产 Electron 与打包后 EXE 均能连接独立数据进程。

## 下一阶段输入

阶段 1（人物卡）只需要新增读取接口和人物领域表，不应修改本阶段的源修订、段落 ID 和证据协议。每个人物属性必须引用一个或多个 `evidence_anchors`；模型推断与原文事实要分字段存储。
