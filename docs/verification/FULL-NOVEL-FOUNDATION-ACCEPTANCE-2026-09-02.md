## 验收中发现并修复

### 自动对白草稿长篇性能

修复前，每处理一个段落都会重新聚合全部 30,818 个检查点，并把完整 item 列表通过 worker IPC 返回主进程。20 分钟时只完成 9,748 段，按该速度对白步骤预计超过一小时。

修复后仍保持“一次 `processNext` 完成一个段落”的暂停/恢复粒度，但改为原子增量更新进度；高频内部响应不再携带完整检查点列表，显式详情查询仍返回全部 item。三次完整十一阶段实测为 94.07–127.58 秒。

### Character Card V2 与可游玩整合包

两张角色卡在人工审阅并达到内容门槛后，从生产桌面的基础稿生成台实际导出。每张卡均在 `data.character_book` 嵌入同一进入点下的关系与地点知识；包内另保留关系世界书、地点世界书、独立 character book、进入点和文件清单。6 个受管资产 SHA-256 全部匹配，第二次点击导出复用同一包目录。随后从页面选择该包执行只读回读，清单、6/6 文件、V2 卡、内嵌/独立 character book、两类世界书、进入点和来源指纹全部通过。

兼容验收使用本机 SillyTavern 1.18.0 源码，但把 config、默认内容和 webpack 缓存全部放在新建的临时 data root；真实调用 `/api/characters/import` 上传包内王扬 JSON 卡，再从 `/api/characters/all` 回读。角色成功落盘，3/3 个内嵌世界书条目保留。服务退出后临时 data root 删除，未修改现有酒馆配置、角色或聊天。

### 章节标题真实格式

源文件包含 17 个以问号或叹号结尾的真实章节标题，以及 11 组相邻重复标题。旧规则误排除强调式标题，又把重复标题分别建章，最终只得到 370 条记录。

现在允许强章节模式中的问号/叹号，只折叠相邻且规范化后同名的标题；非相邻同名章节仍保留。最终正确得到 375 个编号章节和 1 个正文前内容节点。

完整机器可读结果：`verification-results/full-novel-foundation-acceptance-result.json`。

## 复现

该验收默认跳过，必须显式启用；可用 `FULL_NOVEL_FOUNDATION_SOURCE` 改用另一份完整 TXT，并用 `SILLYTAVERN_SOURCE_ROOT` 指定包含 `package.json`、`server.js`、`node_modules` 和同版本 `data/_webpack` 缓存的 SillyTavern 1.18.0 源码目录：

```powershell
npx playwright test tests/e2e/full-novel-foundation-acceptance.spec.ts
```
