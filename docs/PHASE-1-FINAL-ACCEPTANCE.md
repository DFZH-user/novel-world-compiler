# 阶段一最终整链验收

验收日期：2026-08-25  
目标版本：0.1.3  
工程 schema：v13

## 结论

阶段一“从小说生成可追溯人物角色卡”的电脑端主流程已经跑通，可以进入第二阶段。当前结论针对工程正确性、可恢复性和小型真实 DeepSeek 样本；百万字真实长篇的人物召回率与最终扮演质量仍需后续持续评测，不能由小样本结果替代。

## 已验证的同一工程整链

1. 新建 `.novelworld` 工程并导入 TXT。
2. 识别章节、段落并生成带上下文重叠的分析分块。
3. 调用模型完成人物普查，保存原文提及和逐字证据。
4. 人工确认人物及重要度。
5. 为确认人物抽取结构化事实，重新校验证据并人工确认。
6. 本地扫描对白、说话人和语言画像。
7. 本地扫描时间表达，模型抽取事件并人工确认进入事件。
8. 计算进入时点的人物状态，不用叙述顺序冒充故事时间。
9. 从已确认事实、状态和对白生成角色卡草稿。
10. 人工保存为已审阅，导出 SillyTavern Character Card V2 JSON。
11. 批量导出达到质量门槛的已审阅卡片。
12. 导出包含数据库、原文、规范文本和校验清单的 `.novelproj` 工程备份。

## 本轮新增验收

- 本地模拟 OpenAI 兼容 API 的单一 Electron 流程完整跑通上述 12 步。
- 真实 `deepseek-v4-flash` 对几行中文小说执行人物普查、人物事实和事件三次请求，在 16.6 秒内完成，并成功导出 `chara_card_v2`。
- 真实测试发现 DeepSeek 会偶尔自创人物事实类别。0.1.3 将已知同义词映射到标准分类；其他非空类别降级到协议预留的 `other`，空类别和无效结构继续拒绝。
- 归一化不修改事实内容、真假状态、来源、置信度和逐字证据；最终入库仍受原文对齐与人工审核门禁约束。

## 仍然保留的边界

- 小样本通过不能代表百万字小说的人物召回率已经达到理想水平。
- 当前输出重点是忠实、可追溯和可人工纠错；人物感染力仍取决于原文对白覆盖、进入时间和可选润色。
- 世界书、人物关系图谱、完整时间轴和世界地图属于第二阶段及后续阶段，不在本次阶段一封版范围内。
