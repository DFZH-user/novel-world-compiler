# Stage 6：单人物安全试聊运行时

日期：2026-09-10

状态：低成本真实安全验收通过；受限重写可用性优化已完成本地回归，真实复测为可选项

## 最小闭环

1. 仅允许使用已经人工审阅、且时间点投影仍有效的角色卡。
2. 从角色卡进入事件生成当前人物状态、最多 6 条确认对白和当前时点允许使用的事实。
3. 把当前确定状态标为角色已知，把歧义状态标为角色存疑；首次在进入点之后公开的确认事实作为禁止命题交给本地输出门。
4. 通过现有加密 API 配置调用文本补全，不使用 JSON mode；DeepSeek V4/V4.1 默认关闭思考，单次输出上限 500 Token。
5. 第一候选先经过本地 `epistemic-output-gate.v1`。不通过时只允许一次受限重写；最终仍不通过则不向界面展示回答。
6. 最终门控由数据 worker 根据持久化规则独立复算，不信任主进程提交的判断结果。
7. 每一轮保存问题、两个候选、最终展示内容、门控违规、上下文指纹、调用次数、Token、失败原因和时间。

## 界面

“角色卡制作”页面新增“单人物安全试聊”面板。只有角色卡已审阅、没有未保存修改、模型和问题均已填写时才能发送。每次发送前明确提示可能产生 1–2 次 API 费用，并要求用户确认。

界面只显示通过输出门的回答。被阻断的原始候选保存在本地审计表中，但不会作为角色回答展示。

## 数据库

schema 从 v25 升级为 v26，新增 `character_runtime_turns`。没有修改角色事实、角色卡、世界书或现有审核状态。

## 当前限制

- 第一版是单轮试聊，不把前几轮对话重新加入模型上下文。
- 未来事实阻断采用已确认公开事实的表面文本匹配；能抓住明确复述，不能代替完整语义判定。
- 角色信念模型尚未与整个生产数据库完全统一；当前确定/存疑来自已有故事状态投影。
- 真实诱导问题的第一次受限重写仍复述了禁止词，因此被最终门控安全阻断；随后已补充“禁止词连否定、引用也不得复述”、中性代称和安全兜底回答，并通过本地回归。由于一次完整真实复测可能再用 2 次调用，不在剩余 1 次授权内冒险执行。

## 真实试聊回执

2026-09-11 使用隔离的王扬夜战校准工程和临时 DeepSeek 配置执行两问：

- 正常问题：1 次调用即通过，回答基于当前已知的称呼、语言和方位异常，没有使用未来事实。
- 诱导剧透问题：2 次调用；两次候选均复述“宜都蛮 / 火祭”，最终被 `epistemic-output-gate.v1` 阻断，`deliveredAnswer` 为空，用户侧没有收到越界内容。

DeepSeek 于 2026-09-10 发布 V4.1 Flash，正式 API 模型 ID 为 `deepseek-flash`；旧 ID `deepseek-v4-flash` 暂时路由到 V4.1 Flash。项目现已把 DeepSeek 调整为首选服务商和默认预设，并保留旧 ID 请求策略兼容。2026-09-11 使用新 ID 完成一次不含小说内容的最小连通测试：HTTP 200，服务端返回模型 `deepseek-flash`，共 23 Token。回执位于 `verification-results/real-quality-review/scene-calibration-46f60d706fb1/deepseek-v41-flash-smoke-2026-09-11.json`。
