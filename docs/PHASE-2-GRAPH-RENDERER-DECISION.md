# 第二阶段关系图渲染器决策

日期：2026-08-28  
状态：已采用并实现

## 结论

采用 Cytoscape.js 3.34.2。当前关系图的主要矛盾不是“能否把十万节点画出来”，而是同一个防剧透快照内需要可靠完成多重边样式、方向箭头、冲突状态、选中详情、连通分量和最短路径。Cytoscape 原生覆盖这些交互和图算法；Sigma 的 WebGL 渲染更适合以大规模显示为主、分析能力另行组合的场景。

## 候选比较

| 维度 | Cytoscape.js | Sigma.js | 本项目判断 |
| --- | --- | --- | --- |
| 渲染模型 | Canvas，可声明节点/边样式和多种布局 | WebGL，面向大规模网络显示 | 当前预期数百节点，二者都可覆盖 |
| 图分析 | 内置遍历、最短路径、连通分量等图算法 | 核心聚焦渲染，通常与 Graphology 组合 | Cytoscape 可减少路径分析的第二套数据模型 |
| 关系表达 | 方向箭头、虚线、数据映射、复合选择器成熟 | 可扩展，但复杂边表达需要更多自定义 | Cytoscape 更贴合真值、来源、极性、冲突四维编码 |
| 超大图上限 | 需要主动简化样式和布局 | WebGL 对数千至数万节点更有优势 | 通过度数筛选、主分量和布局降级控制当前规模 |
| TypeScript / 依赖 | 包含类型声明，零运行时依赖 | TypeScript 生态良好，需要 Graphology 数据层 | 当前引入面更小 |

依据：[Cytoscape.js 官方文档](https://js.cytoscape.org/)说明其支持图论分析、选择器、样式和布局；[Sigma.js 官方文档](https://www.sigmajs.org/)将其定位为基于 WebGL 的交互式网络渲染库，并以 Graphology 作为图数据模型。

## 本机性能样本

命令：`npm run benchmark:graph`  
环境：项目当前 Node 运行时；Cytoscape headless + style enabled。这个样本用于确定布局阈值，不等同于 GPU 浏览器帧率基准。

| 节点 / 边 | 布局 | 初始化 | 布局 | 堆增量 |
| --- | --- | ---: | ---: | ---: |
| 100 / 300 | cose | 20.5 ms | 124.6 ms | 7.6 MB |
| 500 / 1,500 | cose | 41.8 ms | 2,048.3 ms | 17.1 MB |
| 2,000 / 6,000 | circle | 106.3 ms | 113.9 ms | 42.2 MB |

## 据此落实的保护措施

- 力导向布局只用于不超过 300 个可见节点的快照；更大图自动切换到同心布局。
- 图谱提供最低度数、置信度、来源、真实性和“仅主连通分量”筛选。
- 搜索、最短路径和详情只消费后端给出的同一份阅读位置投影，不会另查未裁剪关系。
- 后端同时裁剪关系、历史、证据和未到达的有效期终点；统计不暴露尚未揭示的关系数量。
- 性能脚本保留在 `scripts/benchmark-relationship-graph.mjs`，升级 Cytoscape 或调整阈值时可重复运行。
