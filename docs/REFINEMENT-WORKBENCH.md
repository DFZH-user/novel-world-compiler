# 统一精修台

状态：第一批已实现（只读分级与跳转）

规则版本：`refinement-triage.v1`

数据库：schema v28，不新增第二套审核状态；v26–v28 仅增加安全试聊、短会话与检索审计

入口：应用左侧“统一精修”或工程总览卡片

## 目标

一键流程会产生分散在人物、事实、对白、时间、事件、地点和关系页面的待审候选。统一精修台把当前修订的这些候选实时聚合成一张有优先级的工作清单，但所有裁决仍在原审核页完成。

## 四条固定边界

1. **实时派生，不复制状态**：精修台每次从现有表计算，不保存自己的“已处理”标记，避免与原审核页形成双重真相；
2. **只看当前修订**：历史修订和其他工程的候选不得混入当前待办；
3. **基础稿就绪不等于正式导出就绪**：只有“必须处理”为零时，`readyForArtifactDrafts` 才为真；建议项和稍后项可以保留，正式入图、世界书和角色卡导出仍服从各自人工确认与质量门槛；
4. **可解释、可回到来源页面**：每类待办提供稳定 kind、数量、样例、分级理由和目标页面。第一批跳到对应审核页，不伪造自动裁决。

## v1 分级规则

### 必须处理

- 当前修订没有已完成的一键基础流程；
- SourceSpan 为 `ambiguous` 或 `invalid`；
- 最新已完成草稿选择中的人物仍为 `pending`；
- 人物事实冲突、状态变化等 `character_fact_relations` 尚未裁决。

这些项目会让来源完整性、核心身份或时间状态不确定，因此阻断下一层基础稿。

### 建议处理

- 人物事实、人物别名、对白说话人、事件、地点身份与地点别名；
- 带类型线索的人物关系候选、正式人物关系二次审核；
- 事件时间关系、人物/地点身份连接建议；
- 空间关系候选、正式空间关系二次审核。

这些项目不阻断先生成可继续精修的基础稿，但会显著影响角色卡、关系图和地图质量。

### 可稍后处理

- 未进入最新草稿集合的人物候选；
- 单独的时间表达式；
- 可选真实地图使用的 WGS84 坐标候选；
- 没有提出关系类型的纯共现线索。

这些信号较弱或不在本轮核心范围，默认不要求一次清空。人物/地点别名按界面的实际审核单位计数；没有独立裁决入口的事件参与者、事件地点、时间连接和地点提及继续由父对象审核流程管理，不伪装成可操作待办。

## 返回契约

worker 返回当前 `revisionId`、规则版本、生成时间、最近流程/选择运行 ID、三层项目总数、`readyForArtifactDrafts` 和分组 issue 列表。issue ID 与 kind 稳定，样例最多五条；列表只读，不触发数据库写入。

计数表示待审“项目数”，不是待办类别数。例如“必须处理 12”可能来自 1 个流程阻断和 11 个核心人物裁决。

## 已验证

- 已完成流程 + 最新选择中的 pending 核心人物会产生阻断；确认后阻断清零；
- 稍后处理的时间表达式不会误阻断基础稿；
- 旧修订的 pending 人物不会进入当前清单；
- 重复读取不会改变 review status 或产生数据库写入；
- 跨进程契约、桌面导航和现有审核页跳转通过类型检查。
