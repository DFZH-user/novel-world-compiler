# Stage 7：有界短会话

日期：2026-09-11

状态：实现完成，本地回归通过；本阶段没有新增付费模型调用

后续进度：本页“下一步”所述的只读检索最小原型已经在 Stage 8 完成；真实 A/B 仍未执行。

## 这一阶段解决什么

Stage 6 只能独立问一句。Stage 7 增加一个可显式开始和结束的短会话，使角色能在几轮交流中引用刚刚已经安全展示给用户的内容，同时不把聊天分支误当成原作事实。

它是后续 A/B 检索对照需要的多轮运行底座，不是长期记忆、按需检索或人物 Skill 的完成证明。

## 安全边界

1. 建立会话时锁定工程修订、人物、进入事件、模型和角色卡来源指纹；这些条件变化后不能悄悄沿用旧会话。
2. 下一轮最多回放最近 6 个 `delivered` 问答；`blocked`、`failed` 和尚未完成的候选都不进入历史。
3. 每一轮仍执行 Stage 6 的本地认知输出门和最多一次受限重写；多轮能力不绕过未来事实阻断。
4. 会话内容明确属于游玩分支，不写入人物事实、对白、状态、世界书或角色卡。
5. 结束会话后不能继续发送；新会话不会自动继承旧会话内容。
6. 原有独立单轮接口继续保留，便于低成本验证和兼容已有调用方。

## 界面与审计

“角色卡制作”中的安全试聊面板现在可在“独立单轮”和“连续短会话”之间切换。活动会话会显示锁定模型、已放行轮数、总轮数和历史上限；每次真正向模型发送前仍要求确认 1–2 次可能费用。

schema 从 v26 升级到 v27：新增 `character_runtime_sessions`，并为 `character_runtime_turns` 增加可空的 `session_id` 与 `turn_index`。旧单轮记录继续有效；会话保存 Token 合计、状态和关闭时间，轮次继续保存候选、门控与错误审计。

## 本地验证

- 桌面端端到端用例新增两轮本地模拟会话，并检查轮次顺序、历史计数、会话汇总与关闭状态。

- 上述测试全部使用本地夹具或模拟服务，没有调用 DeepSeek，也没有改动真实小说工程。
