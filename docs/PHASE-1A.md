# 阶段 1A：人物普查与候选审核

## 当前批次目标

阶段 1A 批次 1–2 回答“小说中有哪些能够独立行动的角色，以及哪些称呼属于同一身份”。本阶段不生成性格档案或最终角色卡。扫描结果必须可恢复、可重做，并能回到原文证据。

## 安全边界

- API 密钥仍由 Electron 主进程通过 `safeStorage` 解密，不会传给渲染进程、数据进程或小说工程。
- 小说正文使用 JSON 数据载荷发送给模型，并在系统提示中明确正文不具备指令权限。
- 模型只能提交候选 JSON，不能直接确认、排除或合并人物。
- 每条入库证据必须重新在指定段落中完成逐字匹配或规范化匹配。
- 只有核心分块中的证据可以创建新候选；重叠上下文只用于消歧。

## 处理链路

```text
活动源修订
  → 当前分块方案
  → 分块人物扫描
  → JSON 契约验证
  → 原文引用重新对齐
  → 人物身份候选与原文提及分离入库
  → 重要度初筛
  → 人工确认、排除和分级
```

## 数据表

- `character_scan_runs`：绑定源修订、分块方案、模型、提示词版本和作业。
- `character_chunk_results`：每个分块的状态、原始 JSON、错误和 Token 用量。
- `person_identities`：可编辑的人物身份候选。
- `person_aliases`：待审核别名及其原文位置。
- `person_mentions`：不可变的原文提及和对齐状态。
- `person_identity_links`：同一人物、不同人物或不确定的关系建议。
- `person_metrics`：提及、章节覆盖、对白、事件和出现跨度指标。
- `person_manual_tiers`：用户手工锁定的重要度分级。
- `person_identity_operations`：别名、关系、合并和拆分的可撤销操作载荷。

人物身份被排除时，原始提及和扫描结果仍然保留。重新改为待审核不会丢失证据。

## 身份审核

- 同名不再自动等于同一人。分块明确给出 `different_person` 时会建立两个独立身份。
- 用户确认 `cannot_link` 后，系统禁止这两个人物合并，除非先撤销或恢复该关系。
- 合并只移动 `person_mentions` 和别名的身份归属，并把来源身份隐藏为已排除；不会删除原文提及。
- 拆分以用户勾选的证据为边界创建新身份，并自动建立不可合并约束。
- 模型产生的同一人、不同人和不确定建议均进入待审核列表，不会自行成为硬约束。
- 身份操作采用逆序撤销栈。撤销合并会把原提及和别名放回来源身份；撤销拆分会恢复原归属并移除拆出的空身份。

## 恢复和幂等

扫描缓存键包含源修订、分块方案、模型、提示词版本和输入哈希。应用异常退出后，运行中的分块恢复为待处理；再次启动同一方案会复用原扫描任务。已经完成的分块不会重复调用或重复写入人物提及。

## 当前未包含

- 完整人物事实、状态切片和语言风格（阶段 1B）。
- 事实冲突审核（阶段 1C）。
- Character Card V2/V3 导出（阶段 1D）。

## 已验证范围

- 有效人物和模型虚构人物的证据隔离。
- 姓名、候选别名、对白和事件指标入库。
- 确认、排除、恢复待审核及人工分级。
- 同方案重复启动直接复用完成结果。
- 数据进程中断后恢复同一扫描任务和分块。
- Electron 中完成导入、生成分块并进入人物普查界面。
- 同名异人不会因姓名相同而被错误折叠。
- 别名审核、身份建议审核、不可合并约束、合并和拆分均可撤销。
- 本地模拟 OpenAI 兼容 API 驱动的完整 Electron 人物扫描和身份审核流程。
