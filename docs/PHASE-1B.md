# 阶段 1B：人物事实档案

## 当前范围

阶段 1B 从阶段 1A 已确认的人物出发，建立可审核、可追溯的人物事实档案。当前产物仍是内部结构化事实，不是最终 SillyTavern 角色卡。研究结论与后续完整分层见 `PHASE-1B-RESEARCH-PLAN.md`。

## 材料收集

每个人物单独建立材料包，来源包括：

- 已通过证据校验的 `person_mentions` 段落；
- 每个提及的前后相邻段落；
- 人物规范名称在正文中的其他命中；
- 用户已经确认的别名在正文中的其他命中；
- 已排除段落不会进入材料包。

材料按原文顺序去重，目标约每 6,000 字符或最多 240 段组成一个批次，10,000 字符作为超长单段硬上限。开始前显示段落数、批次数和近似输入 Token，避免为每个人物重复上传整本小说。

用户可以选择：

- **单轮精确**：一次检查明示事实、来源性陈述和谨慎的行为推断，费用较低。
- **双轮补漏**：第一轮聚焦明示与来源性陈述，第二轮单独补行为推断、状态变化和遗漏；界面按两倍输入量预估费用。

## 事实契约

事实分类包括：

- `identity`：身份、年龄、职业、阵营等；
- `appearance`：外貌、服装和标志性物品；
- `personality`：由行为支持的性格与处事倾向；
- `ability`：能力、知识、武力和限制；
- `motivation`：目标、执念、恐惧和需求；
- `background`：出身、经历和重要过往；
- `status`：受伤、升级、失忆、死亡等阶段状态；
- `secret`：故事内隐藏身份和秘密；
- `speech`：称呼、语气、口头禅和语言习惯；
- `relationship`：人物对其他角色的关系与态度；
- `other`：无法安全归入以上分类的事实。

每条事实保存来源类型、置信度、可见性、可选生效区间、审核状态和一个或多个证据。

批次 2 进一步把事实来源拆为旁白断言、人物自述、他人陈述、传闻、主观看法和行为推断，并独立保存文本断言、存疑、争议、被否定或未知等证据状态。真实性、可见性和信息来源互不混用。

## 明示与推断

- `explicit`：原文直接陈述。人物自述、传言和他人评价需要在事实文本或说明中保留来源，不自动视为客观真相。
- `inferred`：根据行为、对白或多处表现归纳。必须保留支持该推断的原文行为，不能用“没有描写”推断否定结论。
- `user` 和 `generated` 已预留给后续人工补全及游玩补全，但本批模型不会写入这两种来源。

## 证据门槛

模型返回的每条事实至少需要一个 `support` 引用。数据进程会重新检查：

- 段落必须属于当前人物材料批次；
- 引文必须在该段落逐字存在，或仅有空白、全半角引号等规范化差异；
- 至少一个支持证据通过；
- 无效、虚构或引用其他批次的证据不会产生正式事实。

## 数据表

- `character_fact_runs`：人物、模型、提示词、材料哈希和作业状态。
- `character_fact_batches`：材料段落列表、批次状态、原始 JSON、错误和 Token 用量。
- `character_facts`：结构化人物事实及审核状态。
- `character_fact_evidence`：事实与稳定原文段落之间的证据关系。
- `character_fact_run_options`：抽取轮次和材料批次目标。
- `character_fact_claim_metadata`：陈述方式、证据状态、陈述者和抽取轮次。

## 当前未包含

- 跨批事实冲突检测和矛盾审核（阶段 1C）。
- 自动合并语义相近但措辞不同的事实。
- 完整人物状态切片和故事内日期映射。
- 对话轮次、语言风格与模型辅助的隐式对白归属；本地对白检测和显式说话人审核已在批次 3 完成。
- Character Card V2/V3 生成与导出（阶段 1D）。

## 已验证

- 未确认人物不能启动档案提取。
- 人物材料按姓名、确认别名、提及及相邻上下文收集。
- 原文明示和行为推断分别保存。
- 虚构证据不会入库。
- 相同人物、材料、模型和提示词版本复用完成任务。
- Electron 本地模拟 API 完成人物普查、确认人物、档案提取、证据显示和事实审核。
