# 阶段 1D 批次 1：证据驱动的角色卡草稿

## 目标格式

第一版导出采用 Character Card V2 JSON。SillyTavern 官方角色管理界面支持从文件导入与导出角色；公开 V2 规范要求：

- 顶层 `spec` 固定为 `chara_card_v2`；
- `spec_version` 固定为 `2.0`；
- 所有角色字段位于 `data`；
- V1 的六个基础字段与 V2 新增字段都保留类型正确的默认值；
- `extensions` 必须存在，并应使用命名空间保存应用专属元数据。

参考：

- https://docs.sillytavern.app/usage/characters/
- https://github.com/malfoyslastname/character-card-spec-v2/blob/main/spec_v2.md

当前先导出 JSON。PNG 角色卡需要头像选择、图像处理和 PNG 文本块嵌入，会在后续单独实现，避免把普通图片伪装成可导入角色卡。

## 本地字段映射

| V2 字段 | 当前来源 |
| --- | --- |
| `name` | 已确认人物的规范姓名 |
| `description` | 进入时刻有效，且已经人工确认、故事证据状态为 asserted 的身份、外貌、能力、背景、状态、秘密、关系及其他事实 |
| `personality` | 性格、动机、语言事实，加上已确认对白的本地统计画像 |
| `scenario` | 用户选择的已确认进入事件，以及不确定状态不得擅自选定的约束 |
| `first_mes` | 根据进入事件和当时地点生成的最小叙事开场，要求人工修改和审阅 |
| `mes_example` | 从人物全书对白前、中、后位置等距选出的最多三条已确认原文，使用 `<START>` 与 `{{char}}` 宏 |
| `creator_notes` | 自动来源、人工复核要求和当前边界 |
| `system_prompt` | 默认空字符串，不覆盖用户全局设置 |
| `post_history_instructions` | 默认空字符串，不覆盖用户全局设置 |
| `alternate_greetings` | 默认空数组，可人工用分隔符添加 |
| `tags` | 本地来源、人物重要度等组织标签 |

## 审核与追溯

每个小说版本、每个人物只保存一份当前草稿。生成或重新生成时保存来源事实数量、确定/不确定状态数量、对白样本数量和来源 SHA256 指纹。“确认”只表示人工确认抽取无误；传闻、存疑、争议、已否定和未知主张即使已确认存在，也不会作为客观角色设定进入草稿。手工编辑任一字段后，界面立即回到“待审阅”。

只有用户执行“保存并标记已审阅”后，导出按钮才可用。导出时重新读取数据库里的已审阅版本，生成标准 JSON 并返回文件 SHA256。`data.extensions.novel_world_compiler` 保存 schema、小说版本、人物、进入事件和来源指纹，但这些扩展元数据不会进入正常提示词字段。

## 当前边界

- 自动草稿完全在本地生成，不调用模型，因此忠实但不会主动文学润色。
- 时间不确定的属性保留全部可能值，不替用户选一个看似顺畅的答案。
- 原文对白只能帮助保持说话习惯，三条样本不等于完整语言风格。
- 故事内可见性还不是“哪个人物知道什么”；当前不会据此生成知识状态。
- 本批不生成角色专属 `character_book`。世界书需要等地点、组织、规则和世界观条目具备统一审核协议后接入。

## 批次 2：证据约束的模型润色

本地草稿先人工审阅，才允许请求模型润色。每次请求只包含当前人物的数据：已确认且故事证据状态为 asserted 的事实属性和值、从全书等距选出的最多 12 条已确认说话人对白、确认进入事件以及五个已审阅草稿字段。不会发送其他人物材料或整本小说。

模型只能建议以下字段：

- `description`
- `personality`
- `scenario`
- `first_mes`
- `mes_example`

每个建议字段必须返回 `source_keys`，而且每个键必须存在于本次提供的 `fact:*`、`quote:*`、`entry:*` 或 `draft:*` 来源集合。不存在的键会导致整个结果拒绝入库。这是范围门禁，不等同于完整语义事实核验，因此建议仍必须人工阅读。

建议入库后与原稿并排展示。用户可以逐字段勾选采用，或排除整次建议。应用前会再次比较当前草稿与生成建议时的原稿；只要草稿已经变化，旧建议就失效，防止异步结果覆盖新编辑。采用任一字段后，角色卡审核状态回到 `draft`，必须重新保存为已审阅才能导出。

模型不能在本流程中修改 system prompt、post-history instructions、标签、作者或版本信息，也不能直接执行导出。

## 批次 3：批量盘点、质量门槛与阶段一封版

角色卡工作区会列出全部已确认且分级为 `core` 或 `important` 的人物。批量补齐只处理没有草稿的人物，已有草稿不会被重新生成或覆盖。某个人物缺少确认事实、无法计算进入状态时，失败原因会单独显示，不影响其他人物。

质量报告是确定性检查，不调用模型，也不宣称判断文学质量。初始 100 分，按以下风险扣分：

- 没有或只有很少的确认事实；
- description、personality 或 scenario 缺失；
- first message 过短；
- 没有示例对白或没有确认说话人对白；
- 进入时刻仍有无法排序的状态；
- 主要提示字段过长，可能挤占聊天上下文。

分数映射为 A、B、C、D。达到 70 分且不存在错误级问题，才算“内容达到门槛”；这与 `reviewed` 人工审核状态相互独立。批量导出只选择内容达标且已审阅的卡片。

批量导出不会覆盖目标文件夹中的同名文件；如果文件已存在，会依次使用 `-2`、`-3` 后缀。每个导出文件都通过与单张导出相同的 V2 构造函数和审核门禁，并返回 SHA256。

## 阶段一完成定义

阶段一的目标是从小说生成可追溯、可审核、可导入 SillyTavern 的主要人物角色卡。完成范围包括：

1. 人物普查、身份合并拆分与重要度分级；
2. 人物事实、信息来源、故事内可见性和证据审核；
3. 对白归属与本地语言画像；
4. 状态变化、事件时间关系和选定进入时刻的人物状态；
5. Character Card V2 草稿、人工编辑和审核；
6. 可选的证据约束模型润色与逐字段采用；
7. 核心/重要人物批量盘点、质量门槛、单张和批量 JSON 导出。

PNG 头像卡不阻塞阶段一完成，因为 JSON 已能承载完整 V2 数据并由 SillyTavern 导入。人物关系图、世界地图、完整世界书和游玩整合属于后续独立阶段。
