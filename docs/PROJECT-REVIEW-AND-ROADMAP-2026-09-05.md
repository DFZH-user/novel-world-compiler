# 小说世界编译器：整体复盘与下一阶段路线

日期：2026-09-05。性质：代码与验收记录复盘、公开同类项目调研、开发建议；不是新增功能的完成报告。

本文件调整《项目现状与后续开发路线-2026-08-31.md》中的“下一批”和人物 Skill 实验顺序，不改变前十批历史验收结论。评估范围是当前工作树、已有验收记录及下文列出的公开资料；外部项目未逐个本地安装或做横向性能测试。

2026-09-11 进度：剧情/知情边界、真实单人物安全试聊、有界短会话和边界优先的只读检索 B 组最小原型已经落地。短会话锁定进入点、角色卡来源、模型和检索模式；检索逐条保存来源、原因和约算 Token。确定性测试证明进入点后的命中会在召回前排除，但真实 A/B 尚未执行，不能据此宣称检索提升质量或成本。下一项是用现有校准样本准备无需立即付费的 A/B 运行包与人工评分表，不提前建设长期记忆或人物 Skill。

## 1. 结论：保留编译器主线，先证明人物真的可用

项目的价值不只是“生成一张人物卡”，而是把中文长篇变成有原文证据、有审核记录、能选择剧情进入点的可游玩资料。继续沿这条主线推进，不需要重建成通用智能体平台。

下一里程碑建议改为：**选择一部小说、一个核心人物和一个剧情进入点，产出一个可审阅、可导入、经真实多轮对话验证的最小场景包。**

推进顺序：剧情与知情边界 → 真实质量基线 → 最小场景包与审核减负 → 按需检索对照 → 有收益再建设人物 Skill 和会话记忆。

## 3. 当前最需要改进的地方

### P0：统一剧情边界，不能只靠提示词提醒“不剧透”

静态代码检查发现以下风险，尚未做真实样本泄漏率测量：

- `electron/worker/character-card-service.ts:49` 的 `representativeQuotes` 读取整部当前修订的已确认对白，没有进入点参数；生成卡片和准备精修分别调用它。后期对白可能进入早期人物的示例。
- 同文件的语言画像查询按人物与修订读取；`prepareRefinement` 的事实查询也没有统一揭示边界。因此只修最终卡片文本不足以阻止未来信息进入模型上下文。
- `electron/worker/story-state-service.ts:190` 的事实集合没有按证据揭示位置过滤；无状态变化、只有一个确认值时，`resolveProperty` 可将其当作 `timeless`。**只有一个值不等于读者在进入点已经知道它。**
- 角色卡描述渲染没有按接收者知情权限过滤。公开、私密、秘密标签不能独自替代“谁在何时知道什么”的判断。

建议统一定义投影上下文，至少区分四项：

1. 故事实际时间：状态在世界里何时有效。
2. 叙述揭示位置：读者读到哪里才能获知。
3. 当前视角：人物本人、其他人物、读者、主持人的知情范围不同。
4. 游玩分支：玩家改变后的状态不是原作的新事实。

先按边界筛掉不允许的证据，再检索、排序、聚合、生成摘要；对白画像、精修提示词、世界书、参考文件、检索索引都复用此规则。不能先把未来内容概括进去，再仅删除原始引用。未知权限默认保守排除并提示审核，不把未知视为公开。

回归用例包括：后期对白直接揭晓身份、全书仅出现一次的晚期秘密、后期倒叙早年事件、他人私密信息、事件先后不确定、进入点之前的正常事实。必须同时覆盖禁止泄漏和允许信息仍可用，避免通过“全部不提供”获得虚假的零泄漏。

### P0：修正人物 Skill 实验，避免比较出虚假的优势

SillyTavern 的世界书已经支持关键词动态激活、递归激活和上下文预算；标题、激活词等元数据不等于送入模型的内容。因此“整份嵌入世界书 JSON 的字符数”不是普通角色卡的实际 Token 基线。[官方 World Info 文档](https://docs.sillytavern.app/usage/core-concepts/worldinfo/)

当前原型中的几个实验缺口：

- `baseline_context_files` 指向完整序列化卡片；按字符数除以 4 估 Token，尤其不能据此判断中文运行成本。
- 用例预先指定 `retrieval_files`，相当于已知该读哪些资料，未验证运行时能否自己选对、选漏或误选。
- 五个单轮问题不能测长对话状态一致性；保存的评估状态明确为 `not-run`。
- 本次定向重跑测试为 **1 通过、1 失败**；失败在测试要求 SKILL 文本包含“按需”，不是实测角色质量失败。后续应增加行为断言，不能仅补词后宣称实验通过。
- 合成验收输出不完全对应最新模板。原型的源内容指纹没有完整覆盖模板变化，生成模板升级应纳入版本与指纹，避免不同内容复用同一产物地址。
- 原型只做了部分整合包检查。应复用已有严格包校验/安全读取能力，覆盖真实路径、重复目标、跨文件指纹等，而不是维护较弱的第二套验证。

写出 `SKILL.md` 只是生成一种文件布局，不表示 SillyTavern 会自动执行它。运行时适配必须单独设计和验收。

## 4. 网上有哪些可借鉴的项目

下面是能力上的相邻项目，不是已经验证与我们等价的替代品。

| 项目 / 研究 | 相似点和可借鉴内容 | 不宜照搬的部分 |
| --- | --- | --- |
| [Lorecard](https://github.com/bmen25124/lorecard) | 从 Wiki 等 URL 生成角色卡与世界书；可借鉴来源选择、预览、模板和请求日志，让生成过程与成本可见 | URL / 百科资料往往包含完整结局，不等于中文长篇逐段证据和剧情边界 |
| [BookNLP](https://github.com/booknlp/booknlp) | 面向书籍的人物、共指、对白说话人等分析；借鉴保守身份归并和独立检验说话人归属 | 主要面向英语，不能假定直接套用即适配中文；全局归并错误会污染后续资料 |
| [ChatHaruhi](https://arxiv.org/abs/2308.09597) | 结合人物设定和剧本记忆支持角色扮演；启发我们检索“相似情境下如何说话”，而非只堆性格形容词 | 剧本记忆不天然带有我们的进入点和知情权限，也不直接证明长篇小说方案有效 |
| [CharacterEval](https://arxiv.org/abs/2401.01275) | 中文、多轮、多个角色维度的评测；借鉴人工质量控制和多轮场景评估 | 百科人物画像可能含全剧信息；旧论文的模型排名不能当作现在的选型结论 |
| [SillyTavern World Info](https://docs.sillytavern.app/usage/core-concepts/worldinfo/) | 已有动态激活和预算机制；必须成为现实基线，也可改善世界书分段和激活词 | 不需要先造一个完整新运行时才获得按需加载；动态激活自身也不保证不剧透 |
| [Graphiti](https://github.com/getzep/graphiti) | 带时间信息的知识图谱、来源事件、增量记忆；借鉴时效与来源追踪 | 暂不引入外部图数据库；对话中声称的新事实不能自动推翻已审阅原作 |
| [SillyTavern MemoryBooks](https://github.com/aikohanasaki/SillyTavern-MemoryBooks/blob/main/readme.md) | 对话场景摘要、记忆整合与状态辅助；借鉴会话记忆分层 | 会话摘要会丢细节或出错，必须保留来源回溯，不能写回原作事实表 |
| [Microsoft GraphRAG](https://github.com/microsoft/graphrag) | 图结构辅助检索与跨文档综合；可借鉴不同问题使用不同检索策略 | 完整索引和全局摘要增加工程及计算成本，当前不需要替换已有 SQLite 架构 |

综合判断：真正值得组合的是 **BookNLP 的细粒度文学证据 + 世界书的动态上下文 + ChatHaruhi 的情境对白记忆 + CharacterEval 的多轮验证**。Graphiti / MemoryBooks 的思想放到后续会话状态层，而不是立即改造核心存储。

## 5. 建议的分批推进与验收门槛

### 第十一批收口：边界与评测基础，不宣称 Skill 已完成

保留现有原型作为实验草稿；先补边界测试，再让卡片、精修和资料投影走统一规则。修改语义后标记受影响产物为待复核，保留原有人工编辑和旧包，不静默覆盖。

交付：边界策略、确定性回归夹具、提示词上下文检查、可解释排除原因、修正后的实验规范。验收：上述正反例均通过；未来或越权证据不进入上下文；不能用一个总分掩盖边界失败。涉及 schema 时单列迁移、备份与旧工程克隆验证。

### 第十二批：真实样本与最小可游玩场景

先选择 1 部已有小说、1 个核心人物、约 2 个关联人物、1 个地点、1 个进入事件。只处理构成这个场景所需的证据、关系、对白和开场，不要求先审核全书所有长尾人物。

新增“范围明确的场景包”应有独立范围清单和依赖闭包，完整包原有门槛保持不变。缺失场景关键证据继续阻断，范围外内容明确标记未覆盖，不用缩小范围伪装全书完成。

先从早、中、晚章节分层抽取约 100 条证据建立人工标注小样本，记录抽样规则，既统计误报也统计漏报。分开衡量人物归并、说话人、事实、关系、时间定位；原文引用准确不代表解释一定正确。模型候选、人工修正前后指标分别保留。

交付一个能在隔离酒馆环境进入实际场景的包，至少包含自然开场、当前行动动机、可互动关系和行动线索。风格与场景创作可审核添加，但必须区分原作事实与创作内容。

同时记录首次可用包耗时、人工审核分钟数、必要纠错次数、实际调用量与费用。付费测试继续使用显式开关，执行前有预算上限，不在本次方案复盘中发起调用。

### 第十三批：先验证检索，再验证 Skill

三组逐步对照，内容底稿、进入点和允许知识范围一致：

| 组别 | 运行配置 | 要回答的问题 |
| --- | --- | --- |
| A | 真实 SillyTavern V2 卡 + 原生世界书激活和预算 | 现有路径实际能做到什么 |
| B | 同一卡片与内容策略，增加可运行的按需检索 | 检索本身是否改善信息选取 |
| C | 在 B 上增加人物行为规则或会话记忆模块 | Skill 层是否有独立增益 |

先做 A / B；B 没有收益就不急着做 C。A 的关键词、常驻项、递归与预算设置固化并合理配置，不能故意用未优化基线。优先用现有 FTS、已确认别名、相关人物和地点的一至两跳检索；观察漏检后再决定是否需要向量。无论检索方式如何，边界过滤都在召回和摘要之前。

先在 1 个进入点运行约 12 类用例、每类 3 次，包含至少 5 类多轮链条（例如 10–20 轮）；预算允许后扩到早、中、晚 3 个进入点。测试事实问答、情境语气、关系变化、地点行动、诱导剧透、他人秘密、未知问题、玩家分支和中途矛盾。合成五题仍可做冒烟测试，但不能当晋级证据。

记录实际组装消息、激活/召回的资料及原因、模型 usage、输入输出 Token、检索和重试调用、延迟、失败与超时；不记录密钥。尽可能固定模型、采样、输出上限、历史和上下文预算。对话允许产生新行动，但不得把编造的原作经历声称为已发生的正典。

评分采用匿名打乱的人工成对比较，分别评价人物语气、事实支撑、知情边界、状态连贯与可玩性；模型评分仅辅助。小样本报告原始数量、平局和失败，不以“胜率 60%”独自证明泛化收益。

晋级条件：固定回归集零边界泄漏、有效事实覆盖不退步、人工质量不低于 A，并在质量或实际成本上至少有一项清晰收益。原型中 Token ≤ 1.1 倍、延迟 ≤ 1.5 倍、调用不增加只能作为待验证的产品预算，不能当已经实现的结论。

### 第十四批及以后：审核减负与独立会话状态

- 审核队列按“影响当前场景的程度”排序，同一事实的重复证据合并展示；批量操作仍需显式确认，支持撤销和查看影响范围。
- 局部重算仅使依赖它的卡片/世界书失效，保留人工修订；展示变更来源和新旧差异。
- 会话存储区分原作事实、已接受的分支状态、未证实推测、摘要。状态附 `branch_id`、来源消息和版本，支持回滚；摘要指回消息，不能自动覆盖原作。
- 多人物自主运行、PNG 正式导出、V3、真实地图服务和外部图数据库，分别在单人物收益、用户交换需求、规范兼容或性能瓶颈出现后再立项。

## 6. 本轮交付与明确未做事项

本轮完成项目复盘、上述官方项目/论文调研及路线修订；核对了未完成原型并定向重跑其测试，结果 1 通过、1 失败。没有运行整套回归、没有修复业务代码、没有新增数据库迁移、没有发起付费模型调用，也没有更改用户小说或酒馆数据。

下一次开发的最小起手任务：**添加“晚期对白 / 孤立晚期事实 / 他人秘密 / 正常已知事实”测试，定义进入点与知情策略，再修复统一资料投影。** 完成后再做真实场景包，不继续把文件生成当作人物 Skill 效果证明。
