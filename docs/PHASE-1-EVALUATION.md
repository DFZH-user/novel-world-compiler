# 阶段一人物角色卡：第一版封版评估

评估日期：2026-08-22  
评估对象：schema v13、应用 0.1.0 的人物卡主链路  
结论状态：本地工程验收完成；真实长篇与 DeepSeek 盲评待用户在应用内安全保存 API 配置及导入评测小说后执行。

## 1. 结论

当前版本已经达到“可生成、可追溯、可人工审核、可导入 SillyTavern”的阶段一目标。它的强项是忠实和可查错，不是一次提示就生成很华丽的成品。基于合成基准、数据库状态检查、导出结构和桌面全流程，暂定工程效果 **82/100（B+）**：适合作为可信底稿，经过一次模型润色和人工审核后使用；尚不能在没有真实小说盲测的情况下宣称人物扮演效果优秀。

| 维度 | 暂定分 | 判断 |
| --- | ---: | --- |
| 事实忠实度 | 18/20 | 事实有原文证据、人工审核和来源指纹；传闻/争议等已与客观设定隔离 |
| 时间一致性 | 18/20 | 能按进入事件解析状态变化；无法排序时明确保留不确定，不按文本顺序猜测 |

| 角色扮演即用性 | 13/20 | 基础稿准确但偏档案式；开场白较保守，人物感染力依赖对白覆盖与可选模型润色 |

## 2. 本次封版复查发现并修正

1. **证据状态混用**：过去“人工确认这条抽取存在”可能把“坊间传言某人是皇子”写成客观身份。现在角色状态、角色卡、润色来源和批量事实数只采用 `truth_status=asserted`；旧工程没有元数据的历史事实继续兼容读取。
2. **对白样本偏向开篇**：过去固定取最早 3/12 条对白，人物后期语气变化可能完全缺席。现在从人物全书已确认对白中等距抽取前、中、后代表样本，并优先避开超长对白。
3. **导出版本漂移**：工程已经是 v13，但 V2 扩展仍硬编码 v12。现在直接读取当前 schema 常量，避免以后再次漂移。

## 3. 与公开同类方案的对比

## 4. 仍需改进的地方

按收益优先排序：

1. **P0：真实长篇金标准与盲评**。至少选择一部短篇/中篇和一部长篇，人工标注 5–10 个主要人物的身份、关键事实、代表对白和 3 个进入时点。用确定性指标测漏检、错配、时间穿越，再让 DeepSeek 只看原文证据和角色卡，盲评忠实度、区分度、可扮演性与开场吸引力。
2. **P0：实际游玩回放评测**。仅看角色卡文本不足以判断效果；固定用户提示进行 10 回合模拟，检查人物是否串台、泄露未来、复读定义、替用户行动和逐步失去语气。
3. **P1：人物知识边界**。当前 `visibility` 不是“谁知道什么”。后续要为事实增加揭示事件/知情人物，角色卡只能知道进入时点该人物已获知的内容。
4. **P1：语义级来源核验**。模型目前必须返回有效来源键，但仍可能用真实来源键支撑来源中不存在的句子。增加逐句事实蕴含/矛盾校验和失败回退。
5. **P1：卡片长度预设**。增加精简/标准/详细三档与字段 Token 预算，让用户在人物完整度和聊天记忆之间选择。SillyTavern 官方文档也提示永久角色定义越长，留给聊天历史的上下文越少。
6. **P2：成品生态**。增加 V2/V3 JSON 和 PNG 回读、未知扩展保留、头像/PNG 卡、版本快照与差异比较；世界书完成后支持 `data.character_book` 绑定。

## 5. DeepSeek 盲评协议

为避免模型“凭自己记得的原著”打分，评测请求只提供：测试人物的原文证据、指定进入事件、导出角色卡以及下列固定量表，不提供项目自评分。每项 0–20 分：

- 事实忠实度：是否只写证据支持的内容，是否把传闻或推测当事实；
- 时间一致性：是否符合指定进入时点，是否泄露未来；
- 人物区分度：去掉姓名后，语言、动机和行为是否仍能区分于其他角色；
- 可扮演性：模型能否据此稳定回应，而不是只复述百科；
- 开场质量：是否自然给用户留下行动空间，不替用户决定。

模型必须返回 JSON：总分、五项分数、逐项证据、严重问题、改进建议和置信度。最终报告同时保留 Token 用量、模型名和提示版本。API 密钥只从 Electron `safeStorage` 解密，不写入小说工程、命令、测试夹具或本报告。

## 6. 当前评测边界

本轮自动回归使用人工构造的小说状态，能证明状态解析、传闻隔离、代表对白、审核门禁和导出格式，但不能代表百万字小说的人物召回率。当前电脑还没有在应用安全存储中保存 API 配置，`D:\xiaoshuo` 也没有用户要评测的真实小说工程，因此 DeepSeek 实际分数尚未生成。完成这两项输入后再执行盲评，不能用本地结构分冒充模型效果分。
