# Stage 8：边界优先按需检索

日期：2026-09-11

状态：最小 B 组原型与本地回归完成；尚未执行真实模型 A/B

## 本阶段完成了什么

在单人物安全试聊和有界短会话上新增 `explainable-v1` 检索模式。用户可以在建立会话前选择固定资料 A 组或按需检索 B 组；选择后随会话锁定，避免中途改变实验条件。

B 组每轮先应用剧情进入点边界，再从以下安全集合召回：

1. 进入点前已有对齐证据的公开确认事实；
2. 已确认人物名与在进入点前成立的确认别名；
3. 当前人物的一跳确认关系及其边界内证据；
4. 进入点前已经公开的确认地点和确认别名；
5. 只查询 `ordinal <= entryOrdinal` 段落的参数化 trigram FTS，短词回退为参数化字面搜索。

默认预算约 600 Token、最多 8 条。这里的 Token 是偏保守的本地约算，只用于组装前预算；真实输入 Token 仍以模型 usage 为准。

## 可解释审计

每一轮保存检索版本、原始问题、进入点、预算、候选数、省略数、实际约算 Token，以及每条资料的：

- 类型与稳定来源 ID；
- 来源段落序号；
- 进入上下文的内容；
- 召回原因与命中词；
- 排名和约算 Token。

界面中的 `RETRIEVAL TRACE` 账页可以展开查看这些信息。检索回执属于试聊审计，不写入原作事实、角色卡或世界书。

## 数据迁移

schema 从 v27 升级到 v28：

- `character_runtime_sessions.retrieval_mode` 锁定 `off` 或 `explainable-v1`；
- `character_runtime_turns.retrieval_json` 保存逐轮完整回执；
- `character_runtime_turns.retrieval_approx_tokens` 保存预算统计。

旧会话迁移后默认为 `off`，旧轮次回读为无检索回执，原有单轮和短会话行为不突变。

## 验证结果

- 正向：询问“林月在哪里等你”能召回进入点前的一跳确认关系与对应原文。
- 反向：询问“青石镇主是谁”时，进入点后的同词原文不会进入候选回执或模型提示词。
- 所有带段落的召回项均满足 `sourceOrdinal <= entryOrdinal`。
- 检索模式、回执与会话轮次可以跨 worker、主进程和 preload 保存与回读。
- TypeScript、56 个 Vitest 文件/180 项测试、2 项关键桌面回归及三部分生产构建通过。
- 本阶段没有调用 DeepSeek，也没有改动真实小说工程。

## 现在还不能宣称什么

- 没有真实 A/B，因此不能说 B 组比 SillyTavern 原生世界书更好或更省 Token。
- 当前只做字面与结构化一跳召回，没有向量检索、重排模型或图数据库。
- 当前约算 Token 不是服务端计费数；真实实验必须同时保存模型 usage。
- `public-entry.v1` 仍是保守的读者公开边界，不等于完整的逐人物私有知识授权。
