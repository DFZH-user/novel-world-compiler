# 一键生成完整世界工程

状态：integrated.10 已实现（十一阶段提取 + 自动定稿 + 三类成品 + 可游玩整合包）

数据库：schema v28（本流程的数据与审核语义不变；v26–v28 仅增加安全试聊、短会话与检索审计）

入口：应用左侧“一键生成”或工程总览的“一键生成”卡片

## 目标

用户导入小说后，只启动一次，程序自动生成可直接使用、可恢复且之后仍可修改的世界工程。系统按证据与置信度裁决尚未处理的候选；用户已有的确认、排除和编辑优先，重跑不会覆盖。

## 当前十一阶段

1. **工程预检**：检查数据库、全文索引、来源文件和基础数据状态；
2. **准备分块**：复用当前分块；没有时才按默认参数生成；
3. **人物普查**：使用 API 设置中的首选模型生成人物候选；
4. **自动草稿选择**：按版本化策略选择本次下游分析对象，不修改人物审核状态；
5. **人物事实草稿**：只对草稿集合提取事实，结果保持 `pending`；
6. **对白草稿**：本地逐段扫描，只关联草稿集合中的当前人物，归属保持 `pending`；
7. **时间表达式草稿**：用本地规则识别日期、相对时间、时刻等，新增表达式保持 `pending`；
8. **事件草稿**：事件模型只接收草稿集合人物；事件、参与者、地点线索和时间连接均保持 `pending`；
9. **地点草稿**：只消费本次事件草稿运行的地点证据，不读取其他待审事件，地点、别名和提及保持 `pending`；
10. **关系草稿**：仅在草稿集合的当前人物内运行本地关系扫描，候选保持 `pending`；不足两人时显式跳过；
11. **自动定稿与成品生成**：裁决尚未处理的人物、事实、对白、时间、事件、地点与关系，选择默认进入点，生成角色卡、关系图、叙事地图；三类门槛全部通过时再自动导出可游玩包。

界面显示总进度和每一步状态。父流程和模型/本地子任务支持暂停、继续、取消和失败重试；已完成步骤不会重复执行。

## 裁决与修改模型

正式数据层继续使用 `pending / confirmed / rejected`。自动定稿只更新 `pending`：有支持证据且达到阈值的记录进入 `confirmed`，弱证据、冲突和低置信记录进入 `rejected`。人工已经处理过的状态与已有角色卡草稿不被自动重写。

当前策略 `character-draft-selection.v2` 纳入所有具备提及证据的核心/重要人物，不再使用旧的 12 人上限；低重要度人物仍保留为世界节点。策略保存候选快照、选择理由和逐项 SHA-256 指纹。所有下游草稿入口会重新验证：

- 选择运行已经完成；
- 选择运行属于当前 revision；
- 人物仍存在且没有被人工拒绝；
- 输入指纹包含选择运行、当前分块/正文和消费者版本。

普通编辑页仍保留逐项确认、排除、合并、拆分和修改能力。质量与修改中心显示来源、置信度、歧义和剩余质量提示，但不再要求用户清空待办才能使用成品。

## 恢复与幂等

- 父流程、步骤、子任务和输入指纹写入工程数据库；
- 人物普查、人物事实、事件和关系沿用分块/分批检查点；
- 草稿选择和对白分别保留逐人物、逐段检查点；

- 事件与关系运行记录保存 `input_mode` 和 `draft_selection_run_id`；
- 同一有效输入复用已完成运行，不重复生成候选；
- 程序异常关闭后，运行中的父步骤转为可继续状态；
- schema v24 的历史已完成流程迁移到 v25 时，四个新增步骤显式标为“历史未执行/跳过”，不伪造运行结果。

## 安全边界

- 自动定稿不修改原始 TXT，不读取或记录明文 API Key；
- 自动定稿不覆盖非 `pending` 的人工裁决，也不覆盖已有角色卡草稿；
- 原文定位歧义会保留状态并降为质量提示，不会伪造成精确坐标；
- 时间关系确认前执行环检测，人物与空间正式关系必须具备支持证据；
- 可游玩包仍使用现有防剧透投影、角色卡质量门槛和逐文件校验。
