# Stage 5：可玩包角色认知策略接入

日期：2026-09-10

状态：本地实现与回归验证通过

## 本阶段完成

1. 将 `point-in-time-context.v1`、`epistemic-guard.v3` 与 `epistemic-output-gate.v1` 的版本关系收束为 `playable-epistemic-runtime.v1`。
2. 只在显式导出可玩整合包时，把角色认知边界追加到 Character Card V2 的 `post_history_instructions`；普通单卡、数据库草稿和人工审阅状态不变。
3. 保留人工填写的提示词，并把编译器规则放在末尾，减少被前文弱化的风险。
4. 卡片扩展记录策略版本、进入事件、段落序号、策略指纹和执行能力边界。
5. 整合包指纹覆盖完整运行时策略；策略变化会生成新的包目录。
6. 只读校验器会拒绝策略缺失、版本/进入点错配、策略指纹错误或 `post_history_instructions` 中规则被删除的包，即使文件 SHA-256 已被重新计算。

## 当前实际能力

- 导入 SillyTavern 等 Character Card V2 宿主后，模型会同时获得当前进入点资料、共享世界书和经过验证的 v3 认知提示词。
- 规则会要求模型区分角色已知、角色信念、角色存疑与叙事层事实，并拒绝把未来剧情或缺失资料当成角色知识。
- 整合包可追踪使用了哪一版策略，回读时可以核验策略是否被删改。

## 明确不宣称的能力

- 外部角色卡不能执行本项目的 TypeScript 输出门；因此不能保证每一次模型回答都被程序化拦截。
- 共享世界书的“已证实”仍是叙事层真实性，不等于每个角色都知情。
- 本阶段没有新增模型调用，也没有消耗 DeepSeek 余额。

## 下一步建议

如果继续建设本项目自有对话运行时，先做一个单人物、单会话的最小闭环：组装时间点上下文 → 调用模型 → 把候选回答交给 `epistemic-output-gate.v1` → 仅在通过后展示；失败时保留审计记录并允许一次受限重写。外部 SillyTavern 路线继续作为低成本可玩基线，不需要为了本阶段反复追加付费验证。
